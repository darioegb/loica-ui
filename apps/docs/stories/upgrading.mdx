# Upgrading to 1.0

This page lists what changed for someone who comes from the 0.x versions of `plume-ui-react`, the name this library was
published under until 0.64. From 1.0 on, the public API follows semver: a breaking change only arrives in a major
version, and this page will list it.

## The library is now `@loica-ui/react`

The name changed, and so did everything that carried it:

<table>
  <thead>
    <tr><th>Before</th><th>Now</th></tr>
  </thead>
  <tbody>
    <tr><td>The package <code>plume-ui-react</code> and its stylesheets (<code>plume-ui-react/styles.css</code>, <code>tokens.css</code>, <code>css/&#42;</code>)</td><td><code>@loica-ui/react</code></td></tr>
    <tr><td><code>--plume-&#42;</code> variables</td><td><code>--loica-&#42;</code></td></tr>
    <tr><td><code>data-plume-&#42;</code> attributes, among them <code>data-plume-color-mode</code></td><td><code>data-loica-&#42;</code></td></tr>
    <tr><td>The cascade layer <code>plume</code></td><td><code>loica</code></td></tr>
    <tr><td>The class <code>plume-root</code> of the <code>ThemeProvider</code></td><td><code>loica-root</code></td></tr>
    <tr><td>The types <code>PlumeMessages</code> and <code>PlumeLocale</code></td><td><code>LoicaMessages</code> and <code>LoicaLocale</code></td></tr>
  </tbody>
</table>

```sh
npm uninstall plume-ui-react
npm install @loica-ui/react
```

Then search your code, your stylesheets and your theme overrides for `plume` and replace each match. `plume-ui-react`
stays on npm, marked as deprecated, and is no longer updated.

The rest of this page uses the new names. If your code still says `plume`, that is the name to look for where the page
says `loica`: the checklist's `data-loica-menu*` is `data-plume-menu*` in a 0.x version.

## Checklist

Search your code for these, one by one. The rest of the page explains each change.

- `classNames`, `inputClassName` and the other loose class props: [every element is a part](#every-element-is-a-part).
- `aria-label` on `AlertDismiss`, `ToastDismiss`, `FileUploadRemove` and `SelectClear`: it is [`label`](#close-and-remove-buttons-take-label).
- `labels`, or a text prop such as `nextLabel` or `dismissLabel`, on any component, and the `overlayClose`, `alert`,
  `button`, `spinner` and `table` keys of a `LocaleProvider`: [the texts](#the-texts-come-from-the-localeprovider).
- `inputRef` on a `DatePicker` or a `TimePicker`, and a `ref` on a `SelectTrigger`, a `Rating` or a `PinInput`: [the ref](#the-ref-goes-to-the-element-the-field-talks-to).
- `data-loica-menu*`, `data-loica-select-control`, `data-loica-tree-*` and other [renamed CSS hooks](#renamed-css-hooks) in your stylesheets.
- `label`, `busy`, `busyText` and `labels` on a `Button`, and `Spinner` anywhere: [`Button` and `Loader`](#button-takes-its-content-as-children-and-spinner-is-loader).
- `Tabs` with an `index` that you never update, and the `active` class of a tab: [Tabs](#tabs-are-controlled-with-the-same-props-as-the-rest).
- `siblingCount`, `boundaryCount` or `count` on a `Paginator`: [other changes](#other-changes-that-dont-throw).
- `variant='unstyled'` anywhere: it now drops [every Loica class](#unstyled-drops-every-loica-class).
- An `Icon`, a `List` or a `Card` that you style: [presentation components](#icon-list-and-card-are-made-of-parts).
- A `BadgeDot`, a `DividerLabel`, a `SkeletonLine` or a part of the `EmptyState`: [single components](#badge-emptystate-divider-and-skeleton-are-single-components).
- `InputGroup`, `InputAddon`, `TextareaCount`, `NumberInputField`, `PinInputCell`, `RatingItem`, `SliderThumb` and the
  other parts of the text fields: [single components](#text-fields-pininput-rating-and-slider-are-single-components).
- `ChipRemove`, `AvatarImage` and the other parts of the `Chip` and the `Avatar`: [single components](#chip-and-avatar-are-single-components-alert-is-made-of-parts).
- Parts used outside their component: [they throw](#parts-outside-their-component-throw).
- Imports from `@plume-ui-react/*`: [one package now](#from-the-plume-ui-react-packages).
- `colorScheme` set to `brown`, `pink`, `purple`, `teal` or `yellow`, a shade such as `primary.700` on a `Loader`,
  `colorVar`, `ColorShade`, or a `--loica-color-<scheme>-<shade>` variable: [the palette](#the-palette-has-the-six-colors-the-components-use).
- `--loica-space-48`, `--loica-container-7xl`, `--loica-font-family-mono`, `--loica-shadow-sm` and the other values that
  [the scales no longer have](#the-scales-keep-the-values-the-components-use).

## From the `@plume-ui-react/*` packages

If you installed the scoped packages (`@plume-ui-react/button`, `@plume-ui-react/input`, `@plume-ui-react/datepicker`,
`@plume-ui-react/use-mask`...), they are replaced by a single package, `@loica-ui/react`. Components, hooks and the
theme are all imported from it, and each module keeps its own `'use client'`, so importing a few of them doesn't bring
the rest.

```sh
npm uninstall @plume-ui-react/button @plume-ui-react/input @plume-ui-react/datepicker
npm install @loica-ui/react
```

```tsx
// Before
import { Button } from '@plume-ui-react/button'
import { useMask } from '@plume-ui-react/use-mask'

// After
import { Button, useMask } from '@loica-ui/react'
```

The styles come from `@loica-ui/react/styles.css`, imported once. The scoped packages are no longer updated.

## `Checkbox`, `Radio` and `Toggle` are bare controls

They render a single `<input>` and no longer take text as `children`, so there is one `<label>` per control. The
visible text comes from `Field`, with the new `inline` orientation (control first, then the label, with the helper
and error text under it). `className` and `style` go to the `<input>`, and `classNames` and the `CheckboxPart`,
`RadioPart` and `TogglePart` types are gone.

```tsx
// Before
<Checkbox classNames={{ label: 'font-semibold' }}>Accept the terms</Checkbox>

// After
<Field label='Accept the terms' orientation='inline'>
  <Checkbox />
</Field>
```

A control that has no visible text needs an `aria-label`. In a `RadioGroup`, give each option its own `Field`:

```tsx
<RadioGroup aria-label='Plan'>
  <Field label='Free' orientation='inline'>
    <Radio value='free' />
  </Field>
  <Field label='Pro' orientation='inline'>
    <Radio value='pro' />
  </Field>
</RadioGroup>
```

## `Button` takes its content as `children`, and `Spinner` is `Loader`

`Button` is a single component. Its content is its `children`, and it takes every attribute of a `<button>` (`form`,
`name`, `value`, `autoFocus`, `onPointerDown`...). `busy`, `busyText`, `labels` and the parts `ButtonIcon`,
`ButtonLabel` and `ButtonSpinner` are gone: the icons go in `iconLeft` and `iconRight`, and the loading state is
`loading` and `loadingText`. Its `data-busy` is `data-loading`. `label` stays, as the content of a Button
without children (`<Button label='Save' />`).

```tsx
// Before
<Button busy busyText='Saving...' label='Save' labels={{ busy: 'Guardando' }} />

// After
<Button loading loadingText='Saving...'>Save</Button>
```

`Spinner` is now `Loader`, with three variants: `spinner` (the default), `dots` and `bars`. `dashed`, `dotted`,
`double`, `thickness` and `speed` are gone; style the `Loader` with CSS for those. Without `colorScheme` it takes the
color of the text around it, instead of the foreground of the theme. One text names it, the `loader` key of the
`LocaleProvider`, which replaces the keys `spinner`, `button` and `table`, and so the `labels` prop of the `Table`.

```tsx
// Before
<Spinner colorScheme='primary' variant='dashed' />
<LocaleProvider messages={{ button: { busy: 'Cargando' }, spinner: { label: 'Cargando' } }}>
  <App />
</LocaleProvider>

// After
<Loader colorScheme='primary' variant='dots' />
<LocaleProvider messages={{ loader: { label: 'Cargando' } }}>
  <App />
</LocaleProvider>
```

## One name for the value callback and for flags

The value of a component is always reported by `onValueChange`, and a flag is a plain adjective, without `is`. The
components that are a single native `<input>` or `<textarea>` (`Input`, `Textarea`, `Checkbox`, `Toggle`, `Radio`)
keep the `onChange` of the element, with its event.

## Every element is a part

In 0.x, a component with inner parts styled them through loose props (`inputClassName`, `backdropClassName`...) and
later through a `classNames` record. Both are gone. When the user writes the structure (the items of a list, the
header and body of a dialog), every element is a part you can import, with its own `className`, `style`, `ref` and
`data-loica-<component>-<part>` attribute. Given no parts, a component renders the same default composition as before;
when a direct child is one of its parts, it renders your composition. When the component draws the element by itself
(the reveal button of an `Input`, the dot of a `Badge`), it is not a part: it carries the same `data-loica-*` attribute
and you style it from the parent. The sections below list each family.

```tsx
// Before
<Input type='password' revealable revealClassName='text-sm' />

// After
<Input type='password' revealable className='[&_[data-loica-input-reveal]]:text-sm' />
```

## The look of the `DatePicker` goes on the `DatePicker`

`variant`, `size` and `shape` style the input and the calendar together, so they go on the `DatePicker` and no
longer on the `DatePickerInput`.

```tsx
// Before
<DatePicker onChange={onChange}>
  <DatePickerInput variant='filled' size='sm' />
  <DatePickerCalendar />
</DatePicker>

// After
<DatePicker onValueChange={onChange} variant='filled' size='sm'>
  <DatePickerInput />
  <DatePickerCalendar />
</DatePicker>
```

## `className` goes to the outermost element

`className` and `style` always land on the outermost element a component renders, and the native control carries a
`data-loica-<component>-field` attribute to style it from there. It changes for the components that wrap their
`<input>` or `<textarea>`:

## The texts come from the `LocaleProvider`

Every text the library shows or announces is changed in one place, the [`LocaleProvider`](?path=/docs/guides-internationalization--docs),
keyed by component and typed as `LoicaMessages`. Texts that carry data are functions. The loose props of 0.x are gone,
and so are the `labels` props of the first 1.0 betas. A change for one section is a nested
provider, and a single text can be set on the part that shows it.

```tsx
// Before
<Paginator nextLabel='Siguiente' previousLabel='Anterior' getPageLabel={(page) => `Página ${page}`} />

// After
<LocaleProvider
  messages={{ paginator: { next: 'Siguiente', previous: 'Anterior', page: (page) => `Página ${page}` } }}
>
  <Paginator />
</LocaleProvider>
```

## Text fields, `PinInput`, `Rating` and `Slider` are single components

`Input`, `Textarea`, `NumberInput`, `PinInput`, `Rating` and `Slider` no longer take `classNames`. They draw their
addons, elements, reveal button, counter, steppers, boxes, stars, track and thumbs themselves, so `InputGroup`,
`InputControl`, `InputAddon`, `InputElement`, `InputField`, `InputReveal`, `TextareaField`, `TextareaCount`,
`TextareaStatus`, `NumberInputField`, `NumberInputDecrement`, `NumberInputIncrement`, `NumberInputHidden`,
`PinInputCell`, `PinInputHidden`, `RatingItem`, `RatingEmpty`, `RatingFilled`, `RatingRadio`, `RatingValueText`,
`SliderBody`, `SliderTrack`, `SliderRange`, `SliderThumb`, `SliderMarks`, `SliderMarkItem` and `SliderMarkLabel` do not
exist. They take no `children`, and all the native attributes of their element. Each element carries a
`data-loica-<component>-<element>` attribute, to style it from the parent.

```tsx
// Before
<Input type='password' revealable classNames={{ input: 'font-mono', reveal: 'text-sm' }} />

// After
<Input
  className='[&_[data-loica-input-field]]:font-mono [&_[data-loica-input-reveal]]:text-sm'
  revealable
  type='password'
/>
```

## `Select` and the pickers are made of parts

`Select`, `DatePicker` and `TimePicker` no longer take `classNames`. Every element they render is a part you can import,
with its own `className`, `style` and `ref`. Given no `children`, they render the same default composition as
before, and a data-driven part (the chips of a `Select`, the days of a `DatePicker`, the options of a `TimePicker`)
takes a render function to style or replace each item.

```tsx
// Before
<DatePicker onChange={onChange} classNames={{ input: 'font-mono' }} />

// After
<DatePicker onValueChange={onChange}>
  <DatePickerInput>
    <DatePickerField className='font-mono' />
    <DatePickerTrigger />
  </DatePickerInput>
  <DatePickerCalendar />
</DatePicker>
```

The button of the pickers is `DatePickerTrigger` or `TimePickerTrigger`, which goes `before` or `after` the field with
`position`. Its icon is the `icon` prop of the `DatePicker` and the `TimePicker` (or the `children` of the trigger), and
its name comes from the `datePicker.openCalendar` and `timePicker.openTimePicker` texts of the `LocaleProvider`.

```tsx
<DatePicker icon={<MyCalendarIcon />} onValueChange={onChange} />
```

## `Chip` and `Avatar` are single components, `Alert` is made of parts

These components no longer take `classNames`. The `Chip` and the `Avatar` export no parts for the elements they draw
by themselves, so `ChipIcon`, `ChipLabel`, `ChipRemove`, `AvatarImage`, `AvatarFallback` and `AvatarStatusDot` do not
exist. What used to be a key of `classNames` is a `data-loica-<component>-<element>` attribute, so you style
it from the parent (`[&_[data-loica-chip-remove]]:opacity-60` in Tailwind), or you put your own element in the prop
that fills it. `children` keeps its meaning: the text of the chip. The `Avatar` takes no `children`; its fallback is
the `fallback` prop.

Every element of the `Alert` is a part you can import (`AlertIcon`, `AlertContent`, `AlertTitle`,
`AlertDescription`, `AlertAction` and `AlertDismiss`), with its own `className`, `style` and `ref`. Given no parts,
it renders the same default composition as before, and `children` keeps its meaning (the text of the alert); the
root switches to your composition when a direct child is one of its parts. With parts, the props that only fill the
default (`icon`, `action` and `dismissible`) have no effect: compose the part instead.

`title` on an `Alert` or a `Card` is no longer the tooltip of the element: it is the title that the component shows,
in an `AlertTitle` or a `CardHeader`, next to a `description`. Use the `title` of an element inside if you want a
tooltip.

```tsx
// Before
<Alert dismissible classNames={{ dismiss: 'opacity-60' }}>Saved</Alert>

// After
<Alert>
  <AlertIcon />
  <AlertContent>Saved</AlertContent>
  <AlertDismiss className='opacity-60' />
</Alert>
```

## Close and remove buttons take `label`

## `unstyled` drops every Loica class

With `variant='unstyled'`, a component and all its parts keep only the classes you give them. Before, a few parts kept
a class of Loica (the vertical and alignment classes of `Tabs`, the disabled class of a `Button`, parts of the calendar
of the `DatePicker`...). What the component needs to work (a flex row, the reset of a `<button>`, the layer that centers
a modal) stays through rules with zero specificity on the `data-loica-*` attributes, so any class of yours wins over
them. It applies to `Alert`, `Badge`, `Button`, `Card`, `DatePicker`, `Icon`, `Input`, `List`, `Loader`, `RadioGroup`,
`Tabs`, `Textarea`, `TimePicker` and `Tree`, among others. If you restyled an unstyled component by overriding a Loica
class, write your own classes on its parts.

## Parts outside their component throw

A part that needs its component to work reads its context, and now throws when it is used outside it, with the name of
the component it expects: `Tab` and `TabPanel` (they took position 0), `SidebarBackdrop`, `SidebarContent`,
`SidebarItem`, `SidebarItemIcon` and `SidebarItemLabel` (they worked with default styles). Put them inside their
`Tabs` or `Sidebar`. The parts of `List` and `Card` don't throw: they need nothing from their root, so they render on
the server with no JavaScript in the browser, and outside their root they are plain elements with no Loica style.

## `Tabs` are controlled with the same props as the rest

`index` is a controlled value, as in the other components. Before, the Tabs copied it into their own state and also
moved by themselves, so a value you never updated seemed to work. Use `defaultIndex` for the starting tab, or give
`index` and `onIndexChange` and update it.

```tsx
// Before
<Tabs index={0}>…</Tabs>

// After
<Tabs defaultIndex={0}>
  <TabList>
    <Tab>Account</Tab>
    <Tab>Billing</Tab>
  </TabList>
  <TabPanels>
    <TabPanel>Account settings</TabPanel>
    <TabPanel>Billing settings</TabPanel>
  </TabPanels>
</Tabs>
```

A selected `Tab` is styled with `[data-active]`, and the `active` class is gone.

## `Badge`, `EmptyState`, `Divider` and `Skeleton` are single components

The `Badge`, the `EmptyState`, the `Divider` and the `Skeleton` are single components: their inner elements (the dot of
the `Badge`, the icon, title, description and action of the `EmptyState`, the label of the `Divider`, the lines of the

in the prop that fills it. `BadgeDot`, `DividerLabel`, `SkeletonLine`, `EmptyStateIcon`, `EmptyStateTitle`,
`EmptyStateDescription` and `EmptyStateAction` do not exist: use `dot` on the `Badge`, the `children` of the `Divider`,

between the description and the action.

## Other changes that don't throw

- `Field` is made of parts: `FieldLabel` (with `FieldRequiredIndicator` and `FieldOptionalText`), `FieldHelperText`
  and `FieldErrorText`, which compose `Text`. Their line height is `normal` instead of `snug`, about 2px taller.
- `ButtonProps` and `InputProps` no longer accept `index`.
- `Toast` with `children` renders them as you write them, where it dropped the ones that were not parts.
- `ModalHeader`, and `DrawerHeader` with it, render a `Heading` with the `heading-5` look and keep `as` for the level.
- The menu of the `Navbar` is in the stack of layers: <kbd>Esc</kbd> closes only the overlay on top, so a `Modal` over
  the open menu no longer closes it too.
- `PaginatorPageSize` takes the parts of the `Select` (`SelectTrigger`, `SelectContent`, `SelectOption`) as children.
- `Paginator` has no `siblingCount`, `boundaryCount` or `count`: it shows as many pages as fit the row (the current
  page, one on each side, the first and the last, at least), and the number of pages is `total` divided by `pageSize`.
- `Rating` and `Tree` have an `outline` variant, and the days in range of the `DatePicker` use `tint-strong`,
  `tint-text` and `tint`, so dark mode changes slightly. The hover of a `filled` field is the overlay token over
  `surface-muted`.

## `Carousel` has three variants

`variant` takes `solid`, `overlay` or `unstyled`: `outline` and `ghost` are gone, and the buttons of a carousel that
still asks for them lose their look. Use `variant='unstyled'` and give the buttons your own classes:

```tsx
// Before
<Carousel variant='outline'>

// After
<Carousel variant='unstyled'>
  <CarouselPrev className='rounded-full border border-gray-300 p-2' />
</Carousel>
```

## `useClickOutside` is removed

The overlays of the library close with their own handling of Escape and of a press outside. If you used the hook for
something else, a `pointerdown` listener does the same:

```tsx
useEffect(() => {
  const close = (event: PointerEvent): void => {
    if (ref.current && !ref.current.contains(event.target as Node)) onClose()
  }
  document.addEventListener('pointerdown', close)
  return () => document.removeEventListener('pointerdown', close)
}, [onClose])
```

## The CSS of Loica is in the layer `loica`

`@loica-ui/react/styles.css` now puts all its rules in `@layer loica`, after declaring `@layer base, loica, components,
utilities;`. A `className` or a rule of yours wins over Loica without `variant='unstyled'` and without raising the
specificity, and Tailwind v4 utilities such as `px-5` win too.

The other side is that CSS with no layer also beats Loica. If you use Bootstrap, `normalize.css` or the preflight of
Tailwind v3, import it into a layer that comes before `loica` (`@import '...' layer(reset)`, after
`@layer reset, base, loica, components, utilities;`), or the reset will remove the padding of the buttons and the
borders of the inputs. See **Customizing styles**.

## The default theme is in the stylesheet

`@loica-ui/react/styles.css` declares the default tokens (`:root` for light mode and
`[data-loica-color-mode='dark']` for what changes in dark mode), so the components render with their colors, spacing
and shadows even without a `<ThemeProvider>`. The provider is still the way to change the theme and the color mode,
and it now writes inline only the variables that differ from the default, so the HTML it renders on the server is
much smaller (a default theme emits about 40 variables instead of more than 300).

Because the default values no longer come from the provider, a variable that is not in your theme is not on the
element: read it with `getComputedStyle` instead of `element.style`. `@loica-ui/react/tokens.css` has only the tokens,
for an app that builds its own components over them.

## `@loica-ui/react/tailwind.css` is removed

The package no longer ships a theme for Tailwind, so it stays independent of any CSS framework. The same theme is in
**Framework integration**: copy it into a file of your app and import that file instead.

```css
/* Before */
@import '@loica-ui/react/tailwind.css';

/* After */
@import './loica-theme.css';
```
