# Design tokens

Every token below is a CSS variable: the default values are declared in `@loica-ui/react/styles.css`
(and alone in `@loica-ui/react/tokens.css`), and `<ThemeProvider>` declares only the ones your theme changes. Each scale
has the values the components use, not a full design system: for the rest, use the scale of your CSS framework. The
Tailwind v4 theme of
<a href='./?path=/docs/guides-framework-integration--docs' target='_top'>Framework integration</a> turns them into
utilities. Colors live on the
dedicated <a href='./?path=/docs/theme-colors--docs' target='_top'>Colors</a> page.

## Spacing

`--loica-space-*`. The half step has a dash instead of the dot in the variable: `--loica-space-1-5`. Tailwind keeps its own spacing (`p-*`, `m-*`, `gap-*`), which has the same
values as the default one of Loica but doesn't follow a theme that changes `spaces`.

<div style={{ display: 'flex', flexDirection: 'column', gap: '0.5rem' }}>
  {Object.entries(defaultTheme.spaces)
    .sort(([a], [b]) => Number(a) - Number(b))
    .map(([key, value]) => (
      <div key={key} style={{ display: 'flex', alignItems: 'center', gap: '1rem' }}>
        <code style={{ width: '5rem' }}>space.{key}</code>
        <div style={{ width: value, height: '0.75rem', background: '#5263ff', borderRadius: '2px' }} />
        <span style={{ opacity: 0.65 }}>{value}</span>
      </div>
    ))}
</div>

## Text styles

`--loica-text-<name>-size`, `-weight`, `-line-height` and `-letter-spacing` · Tailwind `text-<name>` (`text-heading-1`, `text-body`, `text-caption`…)

A text style is a size, a weight, a line height and a letter spacing used together. They are made of the scales above,
so changing `fontSizes` changes the styles too. `Heading` and `Text` use them, and so does the header of the `Modal`. The titles of components that have a `size` (`Card`, `Alert`, `EmptyState`, `Stepper`) stay relative to it, in `em`, so they scale with it. A `Heading` or a `Text` that goes inside a component with its own size takes the same behavior with `size="inherit"`: it follows the font size around it, and keeps the rest of its style.

<div style={{ display: 'flex', flexDirection: 'column', gap: '0.75rem' }}>
  {Object.entries(defaultTheme.textStyles).map(([key, style]) => (
    <div key={key} style={{ display: 'flex', alignItems: 'baseline', gap: '1rem' }}>
      <code style={{ width: '8rem', flexShrink: 0 }}>{key}</code>
      <span
        style={{
          fontFamily: defaultTheme.typography.fontFamily,
          fontSize: style.fontSize.replace(/var\(--loica-font-size-(.+)\)/, (_, name) => defaultTheme.typography.fontSizes[name]),
          fontWeight: style.fontWeight.replace(/var\(--loica-font-weight-(.+)\)/, (_, name) => defaultTheme.typography.fontWeights[name]),
        }}
      >
        The quick brown fox
      </span>
    </div>
  ))}
</div>

## Containers

`--loica-container-<size>` · Tailwind `max-w-<size>`, `w-<size>`

The named widths of the library, with the values of Tailwind v4. Use them for the max width of a dialog, a panel or a page. The `Modal` uses `sm`, `lg` and `3xl` for its sizes `sm`, `md` and `lg`, and the `Container` takes any of them: `5xl` (`64rem`) and `7xl` (`80rem`) are for a page.

<ul>
  {Object.entries(defaultTheme.containers).map(([key, value]) => (
    <li key={key}>
      <code>container.{key}</code> → {value}
    </li>
  ))}
</ul>

## Breakpoints

`@media (--<name>)` and `@media (--below-<name>)` in the CSS of the components · Tailwind `sm:`, `md:`…

A `var()` doesn't work inside `@media`, so the breakpoints are not CSS variables: the build writes them into the media
queries of the components, and `theme.breakpoints` is for your own code. They are the ones of Tailwind v4.

<ul>
  {Object.entries(defaultTheme.breakpoints).map(([key, value]) => (
    <li key={key}>
      <code>breakpoints.{key}</code> → {value}
    </li>
  ))}
</ul>

## Focus ring, borders, controls and states

<ul>
  <li><code>--loica-focus-ring-width</code>, <code>-offset</code>, <code>-inset</code> and <code>-color</code> → {defaultTheme.focusRing.width}, {defaultTheme.focusRing.offset}, <code>{defaultTheme.focusRing.inset}</code>, <code>{defaultTheme.focusRing.color}</code>. Every ring around a control uses the offset, and the rings drawn inside an item (a row of a list or a menu, a day of the calendar) use the inset, so changing them in the theme moves all of them. The color is the fallback of the rings that have no <code>colorScheme</code>: the others take the <code>text</code> color of their scheme.</li>
  <li><code>--loica-border-width-thin</code>, <code>-medium</code> and <code>-thick</code> → {defaultTheme.borderWidths.thin}, {defaultTheme.borderWidths.medium}, {defaultTheme.borderWidths.thick}</li>
  <li><code>--loica-control-height-sm</code>, <code>-md</code> and <code>-lg</code> → {defaultTheme.controlHeights.sm}, {defaultTheme.controlHeights.md}, {defaultTheme.controlHeights.lg} · Tailwind <code>h-control-md</code></li>
  <li><code>--loica-opacity-disabled</code> → {defaultTheme.opacities.disabled} · Tailwind <code>opacity-disabled</code></li>
  <li><code>--loica-overlay-hover</code> and <code>-active</code> → {defaultTheme.overlays.hover}, {defaultTheme.overlays.active}: how much of the text color covers an item under the pointer or pressed, as in <code>color-mix(in srgb, currentcolor var(--loica-overlay-hover), transparent)</code>. Being a part of the text color, they work on any surface and in both modes.</li>
  <li><code>--loica-target-min</code> → {defaultTheme.targets.min}: the smallest box a pointer has to hit (WCAG 2.5.8), for the small buttons and the dots.</li>
  <li><code>--loica-border-hover</code> → {defaultTheme.semantic.borderHover}: the border of a field under the pointer, lighter than <code>--loica-border-strong</code> in dark mode.</li>
  <li><code>--loica-backdrop</code>, the color behind a Modal or a Sidebar panel → {defaultTheme.semantic.backdrop} · Tailwind <code>bg-backdrop</code></li>
</ul>

The shadows and the backdrop have their own values in dark mode, because a dark shadow needs more opacity to be seen.
