# Internationalization

Every text the library shows or announces can be translated, and the library does not depend on any i18n package.
You give it plain strings (or functions, for the texts that carry data) from whatever you already use: react-intl,
i18next, next-intl, Lingui or your own dictionary.

There are three ways to give the texts, and they combine.

## Once for the whole app: `LocaleProvider`

`LocaleProvider` takes the messages of every component in one place. A component takes its texts from the
closest provider, then from the English default. No component takes a `labels` prop.

```tsx
import { LocaleProvider, type PlumeMessages } from 'plume-ui-react'

const es: PlumeMessages = {
  close: { label: 'Cerrar' },
  datePicker: { apply: 'Aplicar', cancel: 'Cancelar', openCalendar: 'Abrir calendario' },
  paginator: { next: 'Siguiente', previous: 'Anterior', page: (page) => `Página ${page}` },
  loader: { label: 'Cargando' },
}

<LocaleProvider locale='es' messages={es}>
  <App />
</LocaleProvider>
```

`messages` is keyed by component (`avatar`, `avatarGroup`, `breadcrumb`, `carousel`, `chip`, `close`, `datePicker`,
`fileUpload`, `input`, `loader`, `navbarToggle`, `numberInput`, `paginator`, `pinInput`, `rating`, `select`,
`sidebarToggle`, `slider`, `stepper`, `textarea`, `timePicker`, `toast`). A text is translated once, under the
component that shows it: `loader` also names the `Loader` of a loading `Button` and of a loading `Table`, and `close`
names the close button of a `Modal`, a `Drawer`, a `Popover`, an `Alert` and a `Toast`. Each value is the same
`Partial<<Name>Labels>` the component takes in its `labels` prop, so you only write what you change. `PlumeMessages`
types all of it.

`locale` is a BCP 47 tag (`es`, `es-AR`, `en-US`). The `DatePicker` uses it for the names of the days and months
and for the format of the date, and its own `locale` prop still wins when you set it. Read it in your own components
with `useLocale()`, which returns the `locale` of the closest provider (or `undefined`).

## For one element: the `label` or `aria-label` of the part

The part that shows a text takes it as a prop: `label` on a small part such as the `Loader`, the close button of a
`Modal` or `CarouselPrev`, and `aria-label` on `PaginatorPage`.
It wins over the provider.

```tsx
<Loader label='Guardando' />
```

## For one part of the app: a nested `LocaleProvider`

A `LocaleProvider` inside another one changes only what it sets and inherits the rest, so a section can have its own
texts without repeating the others. Messages are merged per component, and an inner `locale` wins.

```tsx
<LocaleProvider locale='es' messages={es}>
  <App />
  <LocaleProvider messages={{ loader: { label: 'Guardando' } }}>
    <Loader />
  </LocaleProvider>
</LocaleProvider>
```

## Changing the language at runtime

`LocaleProvider` reads its props on every render, so changing the language is changing the props. The components
below update on their own, with no remount. Define the messages outside the component, or memoize them, so they keep
their identity between renders.

```tsx
const messages = { en, es }

function Root({ children }) {
  const [language, setLanguage] = useState<'en' | 'es'>('en')

  return (
    <LocaleProvider locale={language} messages={messages[language]}>
      <LanguageSwitch onChange={setLanguage} />
      {children}
    </LocaleProvider>
  )
}
```

## With an i18n library

Build the messages from your library and pass them to the provider. When the library changes the language, your
component renders again and the new messages reach every component.

```tsx
// react-intl
function PlumeLocale({ children }) {
  const intl = useIntl()
  const messages = useMemo<PlumeMessages>(
    () => ({
      close: { label: intl.formatMessage({ id: 'close' }) },
      paginator: {
        next: intl.formatMessage({ id: 'paginator.next' }),
        page: (page) => intl.formatMessage({ id: 'paginator.page' }, { page }),
      },
    }),
    [intl],
  )

  return (
    <LocaleProvider locale={intl.locale} messages={messages}>
      {children}
    </LocaleProvider>
  )
}
```

```tsx
// i18next
function PlumeLocale({ children }) {
  const { t, i18n } = useTranslation()
  const messages = useMemo<PlumeMessages>(
    () => ({
      close: { label: t('close') },
      paginator: { next: t('paginator.next'), page: (page) => t('paginator.page', { page }) },
    }),
    [t],
  )

  return (
    <LocaleProvider locale={i18n.language} messages={messages}>
      {children}
    </LocaleProvider>
  )
}
```

Plume also exports a `useLocale`, so import the one of next-intl with another name:

```tsx
// next-intl
'use client'

import { useLocale as useIntlLocale, useTranslations } from 'next-intl'

function PlumeLocale({ children }) {
  const t = useTranslations('plume')
  const locale = useIntlLocale()
  const messages = useMemo<PlumeMessages>(
    () => ({
      close: { label: t('close') },
      paginator: { next: t('paginator.next'), page: (page) => t('paginator.page', { page }) },
    }),
    [t],
  )

  return (
    <LocaleProvider locale={locale} messages={messages}>
      {children}
    </LocaleProvider>
  )
}
```

## Server components

`LocaleProvider` is a client component. Render it once in the root layout and every component of the library below
it reads the messages, also when the page is rendered on the server.
