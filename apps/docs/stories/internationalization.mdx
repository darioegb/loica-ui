# Internationalization

Every text the library shows or announces can be translated, and the library does not depend on any i18n package.
You give it plain strings (or functions, for the texts that carry data) from whatever you already use: react-intl,
i18next, next-intl, Lingui or your own dictionary.

There are three ways to give the texts, and they combine.

## Once for the whole app: `LocaleProvider`

`LocaleProvider` takes the messages of every component in one place. A component takes its texts from the
closest provider, then from the English default. No component takes a `labels` prop.

```tsx
import { LocaleProvider, type LoicaMessages } from '@loica-ui/react'

const es: LoicaMessages = {
  close: { label: 'Cerrar' },
  datePicker: { apply: 'Aplicar', cancel: 'Cancelar', openCalendar: 'Abrir calendario' },
  paginator: { next: 'Siguiente', previous: 'Anterior', page: (page) => `Página ${page}` },
  loader: { label: 'Cargando' },
}

<LocaleProvider locale='es' messages={es}>
  <App />
</LocaleProvider>
```

`messages` is keyed by component, with the keys of the table below. A text is translated once, under the component
that shows it: `loader` also names the `Loader` of a loading `Button` and of a loading `Table`, and `close` names the
close button of a `Modal`, a `Drawer`, a `Popover`, an `Alert` and a `Toast`. Each value is partial, so you only write
what you change. `LoicaMessages` types all of it, and a component with several texts exports their type as
`<Name>Labels` (`PaginatorLabels`, `DatePickerLabels`...).

A text written with arguments is a function that gets them and returns the string, like `page` in the example above.
The others are strings.

`locale` is a BCP 47 tag (`es`, `es-AR`, `en-US`). It does not pick the texts, which are the ones you give in
`messages`: it sets how the components write data, with `Intl`. The `DatePicker` uses it for the names of the days and
months and for the format of the date (and for the first day of the week, with `weekStartsOn='locale'`), the `Paginator` for the numbers of its summary (`12.345` in `de`), the
`FileUpload` for the size of a file (`1,5 kB` in `es`, `1,5 ko` in `fr`), the `NumberInput` for its decimal separator (`1,5` in `es`) and
the `ProgressBar` for its percentage (`50 %` in `de`). The default texts that write a number (the stars of the `Rating`, the counter of the `Textarea`, the `+2` of the `Select` and of the `AvatarGroup`, the slides of the `Carousel`, the cells of the `PinInput`) write it with the digits and the thousands separator of the locale (`٣` in `ar-EG`, `1.200` in `de`). The `Table` sorts text with it, and the search of `Select`, the
filter of `Table`, the typeahead of `Select`, `DropdownMenu` and `Tree`, and the initials of `Avatar` change the case
with it (in `tr`, `i` is `İ`). The components that take a `locale` prop of their own let it win over the
provider, and all fall back to `en`. Read it in your own components with `useLocale()`, which returns the `locale` of the
closest provider (or `undefined`).

The `NumberInput` shows only the decimal separator by default. For thousands separators, a currency, a percentage or a
unit, spread `numberFormat(locale, options)` on it: it gives the `format` and the `parse` that reads it back, with the
options of `Intl.NumberFormat`. Type the separators of the locale, because a dot is a thousands separator in `es` and
`de`.

```tsx
import { NumberInput, numberFormat } from '@loica-ui/react'

const euros = numberFormat('es', { currency: 'EUR', style: 'currency' })

<NumberInput {...euros} aria-label='Price' defaultValue={1234.5} />
```

## For one element: the `label` or `aria-label` of the part

The part that shows a text takes it as a prop, and it wins over the provider: `label` on the `Loader`, on
`TableLoading`, on a close button (`ModalClose`, `AlertDismiss`, `ToastDismiss`...), on `NavbarToggle`,
`SidebarToggle`, `CarouselPrev` and `CarouselNext`, and `aria-label` on `PaginatorPage`, `PaginatorNext` and the other
buttons of the `Paginator`. The texts of an element a component draws by itself, such as the reveal button of an
`Input` or the steppers of a `NumberInput`, have no prop: change them with a nested provider.

```tsx
<Loader label='Guardando' />
```

## For one part of the app: a nested `LocaleProvider`

A `LocaleProvider` inside another one changes only what it sets and inherits the rest, so a section can have its own
texts without repeating the others. Messages are merged per component, and an inner `locale` wins.

```tsx
<LocaleProvider locale='es' messages={es}>
  <App />
  <LocaleProvider messages={{ loader: { label: 'Guardando' } }}>
    <Loader />
  </LocaleProvider>
</LocaleProvider>
```

## Changing the language at runtime

`LocaleProvider` reads its props on every render, so changing the language is changing the props. The components
below update on their own, with no remount. Define the messages outside the component, or memoize them, so they keep
their identity between renders.

```tsx
const messages = { en, es }

function Root({ children }) {
  const [language, setLanguage] = useState<'en' | 'es'>('en')

  return (
    <LocaleProvider locale={language} messages={messages[language]}>
      <LanguageSwitch onChange={setLanguage} />
      {children}
    </LocaleProvider>
  )
}
```

## With an i18n library

Build the messages from your library and pass them to the provider. When the library changes the language, your
component renders again and the new messages reach every component.

```tsx
// react-intl
function LoicaLocale({ children }) {
  const intl = useIntl()
  const messages = useMemo<LoicaMessages>(
    () => ({
      close: { label: intl.formatMessage({ id: 'close' }) },
      paginator: {
        next: intl.formatMessage({ id: 'paginator.next' }),
        page: (page) => intl.formatMessage({ id: 'paginator.page' }, { page }),
      },
    }),
    [intl],
  )

  return (
    <LocaleProvider locale={intl.locale} messages={messages}>
      {children}
    </LocaleProvider>
  )
}
```

```tsx
// i18next
function LoicaLocale({ children }) {
  const { t, i18n } = useTranslation()
  const messages = useMemo<LoicaMessages>(
    () => ({
      close: { label: t('close') },
      paginator: { next: t('paginator.next'), page: (page) => t('paginator.page', { page }) },
    }),
    [t],
  )

  return (
    <LocaleProvider locale={i18n.language} messages={messages}>
      {children}
    </LocaleProvider>
  )
}
```

Loica also exports a `useLocale`, so import the one of next-intl with another name:

```tsx
// next-intl
'use client'

import { useLocale as useIntlLocale, useTranslations } from 'next-intl'

function LoicaLocale({ children }) {
  const t = useTranslations('loica')
  const locale = useIntlLocale()
  const messages = useMemo<LoicaMessages>(
    () => ({
      close: { label: t('close') },
      paginator: { next: t('paginator.next'), page: (page) => t('paginator.page', { page }) },
    }),
    [t],
  )

  return (
    <LocaleProvider locale={locale} messages={messages}>
      {children}
    </LocaleProvider>
  )
}
```

## Server components

`LocaleProvider` is a client component. Render it once in the root layout and every component of the library below
it reads the messages, also when the page is rendered on the server.
