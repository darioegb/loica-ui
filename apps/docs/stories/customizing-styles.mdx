# Customizing styles

Every component can be restyled, from a light touch to a full replacement. Pick the lightest option that does what you
need.

## `className` in every variant

`className` and `style` of a component go to the outermost element it renders. The elements a component draws by itself
carry a `data-loica-<component>-<element>` attribute, so you style them from the parent, and the ones you compose
(the items of a `List`, the header of a `Modal`) are parts you can import, each with its own `className`, `style` and
`ref`:

```tsx
<Input
  className='mt-4 [&_[data-loica-input-field]]:font-mono [&_[data-loica-input-reveal]]:opacity-60'
  revealable
  type='password'
/>
```

The class is added **next to** the Loica classes of the part, in the `outline`, `filled`, `solid` and every other
variant. It does not replace them, but it wins: the CSS of Loica is in the cascade layer `loica`, and CSS with no layer
beats CSS in a layer whatever its specificity, so `px-5` or a rule of yours for the same property always overrides the
one of Loica.

## Cascade layers

`@loica-ui/react/styles.css` starts with `@layer base, loica, components, utilities;` and puts everything inside
`@layer loica`. The order is the one of the layers that come before, so:

- **Your own CSS and the utilities of Tailwind v3**: no layer, so they win over Loica. Nothing to do.
- **Tailwind v4**: its utilities are in the layer `utilities`, which comes after `loica`, so they win. Declare the
  order first if you import Tailwind before Loica: `@layer theme, base, loica, components, utilities;`.
- **A reset with no layer** (Bootstrap's reboot, `normalize.css`, and the **preflight of Tailwind v3**) **also beats
  Loica**: its `button { padding: 0 }` or `* { border-width: 0 }` would strip the styles of the buttons and the inputs.
  Import it into a layer that comes before `loica`. With Tailwind v3, turn the preflight off (`corePlugins: {
  preflight: false }`) and import a reset of your own the same way:

```css
@layer reset, base, loica, components, utilities;

@import 'bootstrap/dist/css/bootstrap.min.css' layer(reset);
@import '@loica-ui/react/styles.css';
```

Tailwind v4's preflight is already in `base`, which comes before `loica`, so it needs nothing.

That layer is for the reboot. When you style Loica with Bootstrap's own classes (`form-control`, `accordion-button`),
import Bootstrap **without a layer**, after `@loica-ui/react/styles.css`: the resets that `unstyled` keeps (`border: 0
solid` on an input, for instance) are in the layer `loica`, and a layer that comes before it would lose to them. Its
reboot then also beats the styled components of Loica, so use `variant='unstyled'` on every component of that page.

The sizes of one component are local variables you can override, like `--sidebar-width` or `--skeleton-height`, and the
widths that components share come from the `--loica-container-*` scale.

Adding what Loica does not set (`mt-4`, `max-w-md`, `ring-2`, `hidden`) always works.

## `variant='unstyled'`

`variant='unstyled'` drops every Loica class and keeps only yours, so you style the component from scratch with
Tailwind or Bootstrap. It applies to the root and to all its parts at once:

```tsx
<Input variant='unstyled' className='rounded-lg border border-gray-200 px-4 py-2.5 focus:ring-2' />

<Input variant='unstyled' className='form-control form-control-lg' />
```

What `unstyled` keeps is what makes the component work, not how it looks: the flex row that holds a chevron, the layer
that centers a modal, the reset of a `<button>` or a `<dialog>`. Those rules have zero specificity, so any class of
yours overrides them. The calendar of the `DatePicker` keeps the grid of days and its header row the same way, and it is
themed with `colorScheme` and the `--datepicker-*` variables.

Every story of Tailwind and Bootstrap in the components shows the component in `unstyled` with those frameworks.

## Styling states

Elements expose their state as attributes, and every one carries `data-loica-<component>-<element>`, so you can style a
state without a class of your own:

```tsx
<Input className='data-[invalid]:border-red-500' />
```

```css
[data-loica-select-option][aria-selected='true'] {
  font-weight: 600;
}
```

The attributes that exist depend on the part (`data-open`, `data-disabled`, `data-invalid`, `data-active`...) and
the ARIA state of the element (`aria-selected`, `aria-checked`, `aria-expanded`) is always there too.

## Colors and tokens

`colorScheme` takes any key of the theme palette, custom ones included, and the tokens of `ThemeProvider` can be
overridden in light and dark mode. See the **Colors** and **Tokens** pages of the Theme section.
