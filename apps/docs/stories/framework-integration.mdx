# Framework integration

Loica ships its own CSS and needs no build plugin, so the setup is the same in every React app: import the stylesheet
once and wrap the app in `<ThemeProvider>`. This page shows where they go in Vite and Next.js, and how to use Loica next
to Tailwind CSS or Bootstrap. The [Examples](?path=/docs/guides-examples--docs) page has a complete app of each kind.

## Vite (or any client-side app)

```tsx
// src/main.tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { ThemeProvider, ToastProvider } from '@loica-ui/react'
import '@loica-ui/react/styles.css'
import { App } from './app'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <ThemeProvider defaultColorMode='system'>
      <ToastProvider>
        <App />
      </ToastProvider>
    </ThemeProvider>
  </StrictMode>,
)
```

`LocaleProvider` goes in the same place when the app is not in English (see
[Internationalization](?path=/docs/guides-internationalization--docs)). In a client-only app the saved color mode can be
read before the first render, from `localStorage`, so `'system'` is the only case that changes after the page loads.

## Next.js App Router

Every component can be rendered from a Server Component. The package keeps `'use client'` on each module that needs it,
so a Server Component imports from `@loica-ui/react` directly. The presentational ones (`Badge`, `Card`, `Divider`,
`EmptyState`, `Heading`, `Icon`, `List`, `Text`, `Skeleton`, the rows and cells of `Table`...) don't need it and
render on the server with no JavaScript in the browser. The page of each component says which one it is, with a
**Server** or **Client** badge under its title, and the API reference marks the parts when they differ.

What a Server Component can't do is pass a function: `onValueChange`, `onClick` or a render prop go in a component of
yours that starts with `'use client'`. Put the providers in one of them too, when they need state:

```tsx
// app/providers.tsx
'use client'

import type { ReactNode } from 'react'
import { ThemeProvider, ToastProvider, type ColorModeSetting } from '@loica-ui/react'

export function Providers({ children, colorMode }: { children: ReactNode; colorMode: ColorModeSetting }) {
  return (
    <ThemeProvider defaultColorMode={colorMode}>
      <ToastProvider>{children}</ToastProvider>
    </ThemeProvider>
  )
}
```

```tsx
// app/layout.tsx
import { cookies } from 'next/headers'
import '@loica-ui/react/styles.css'
import { Providers } from './providers'

export default async function RootLayout({ children }) {
  const saved = (await cookies()).get('color-mode')?.value
  const colorMode = saved === 'dark' ? 'dark' : 'light'

  return (
    <html lang='en'>
      <body>
        <Providers colorMode={colorMode}>{children}</Providers>
      </body>
    </html>
  )
}
```

**No theme flash.** The server renders the mode it is given, so read the one the user picked from a cookie, as above,
and save it there when it changes (a Server Action that sets the cookie, next to `setColorMode` of `useTheme()`).
`'system'` can't be known on the server: it renders light and switches to dark after the page hydrates, so it only has
no flash for the users whose system is light.

The directives live in the ESM build, which is what Next.js and the other bundlers resolve. The CommonJS build is a
single file with none.

## Router links

`SidebarItem`, `NavbarItem`, `NavbarBrand`, `BreadcrumbLink` and a `Button` with `href` render an `<a>`, so a click
reloads the page and a router can't prefetch the target. Give the link component of your router once, with a
`LinkProvider`, and they render it instead. It gets `href` and the rest of the attributes of an anchor, and has to
forward the `ref` and `onClick` to its element, as the link of Next.js and React Router do.

```tsx
// app/providers.tsx
'use client'

import Link from 'next/link'
import type { ReactNode } from 'react'
import { LinkProvider } from '@loica-ui/react'

export function Providers({ children }: { children: ReactNode }) {
  return <LinkProvider component={Link}>{children}</LinkProvider>
}
```

The link of React Router takes `to` and not `href`, so wrap it:

```tsx
import { forwardRef, type ReactNode } from 'react'
import { Link as RouterLink } from 'react-router'
import { LinkProvider, type LinkComponentProps } from '@loica-ui/react'

const Link = forwardRef<HTMLAnchorElement, LinkComponentProps>(({ href, ...rest }, ref) => (
  <RouterLink {...rest} ref={ref} to={href} />
))
Link.displayName = 'Link'

export function Links({ children }: { children: ReactNode }) {
  return <LinkProvider component={Link}>{children}</LinkProvider>
}
```

A link that is `disabled` stays a plain `<a>` without `href`, so it never reaches the router. The nearest
`LinkProvider` wins, so a part of the page can use another one.

## Tailwind CSS v4

The components work as they are next to Tailwind, and with `variant='unstyled'` you style them with utilities. This is
all it takes:

```css
@layer theme, base, loica, components, utilities;

@import 'tailwindcss';
@import '@loica-ui/react/styles.css';

@custom-variant dark (&:where([data-loica-color-mode='dark'], [data-loica-color-mode='dark'] *));
```

The first line puts the layers in order, so the utilities win over the CSS of Loica (see
[Customizing styles](?path=/docs/guides-customizing-styles--docs)). The last one is optional: it makes `dark:` follow
the color mode of Loica instead of the system preference.

The utilities of Tailwind can already read any variable of Loica, such as `bg-(--loica-color-primary-solid)`.

### Optional: utilities with the tokens of Loica

If you style with Tailwind and want it to match the components, put the theme in a file of your app, `loica-theme.css`
(<a href={`data:text/css;charset=utf-8,${encodeURIComponent(sandbox.tailwindTheme)}`} download='loica-theme.css'>download it</a>
or copy it from the end of this section), and import it after the CSS of Loica:

```css
@import '@loica-ui/react/styles.css';
@import './loica-theme.css';
```

It turns the tokens of Loica into utilities: the colors of every scheme and of the page (`bg-primary-solid`,
`text-primary-on-solid`, `bg-surface`, `border-border`), the text styles (`text-heading-1`, `text-body`), the font
family (`font-loica`), sizes, weights, line heights and letter spacings, the radii, the shadows, the container widths
(`max-w-md`) and the easings, plus `z-modal`, `duration-fast`, `opacity-disabled` and `h-control-md`. The shades of a
color are not variables, so there is no `bg-primary-500`, and the values a scale of Loica doesn't have (`shadow-sm`,
`max-w-xl`) stay the ones of Tailwind. Loica doesn't ship this file, so it stays independent
of any CSS framework: keep only the utilities you use, or rename them.

The utilities point to the variables of Loica (`@theme inline`), so they follow the theme, a nested provider and the
color mode. The spacing and the breakpoints are the ones of Tailwind, which are also the default ones of Loica: a
theme that changes `spaces` or `breakpoints` doesn't change `p-4` or `md:`. The **Tailwind** example of every
component uses this theme.

## Tailwind CSS v3

There is no theme file for Tailwind v3: map the variables you need in `tailwind.config.ts`. Turn the preflight off,
because a reset with no layer beats the CSS of Loica, and import a reset of your own into a layer before `loica`
([Customizing styles](?path=/docs/guides-customizing-styles--docs) explains why):

```ts
// tailwind.config.ts
export default {
  content: ['./src/**/*.{ts,tsx}'],
  corePlugins: { preflight: false },
  darkMode: ['class', '[data-loica-color-mode="dark"]'],
  theme: {
    extend: {
      colors: {
        primary: {
          solid: 'var(--loica-color-primary-solid)',
          'on-solid': 'var(--loica-color-primary-solid-contrast)',
          text: 'var(--loica-color-primary-text)',
        },
        surface: 'var(--loica-surface)',
        foreground: 'var(--loica-foreground)',
        border: 'var(--loica-border)',
      },
      borderRadius: { 4: 'var(--loica-radius-4)' },
    },
  },
}
```

Every token is a variable named `--loica-<group>-<name>` (`--loica-color-primary-solid`, `--loica-space-4`,
`--loica-shadow-md`), listed in [Tokens](?path=/docs/theme-tokens--docs). For a filled surface use `solid` with `solid-contrast`, and for colored text `text`: they keep a contrast of 4.5:1 in light and
dark.

## Bootstrap, or any other framework

Give the component `variant='unstyled'` and the classes of the framework:

```tsx
<Button className='btn btn-primary' variant='unstyled'>Save</Button>
<Input className='form-control' variant='unstyled' />
```

Bootstrap's reboot has no layer and beats Loica, so import it after the CSS of Loica when the page styles the
components with Bootstrap, or into a layer before `loica` when it doesn't. Every component page has a **Bootstrap**
example, and [Customizing styles](?path=/docs/guides-customizing-styles--docs) has both setups.
